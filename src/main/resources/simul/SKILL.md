simul 시나리오는 유저가 앱에서 하는 흐름 하나를 **자연어 스텝**으로 쓴 .md 파일이다. 모델이 스텝을 한 줄씩 읽고
기기를 조작해 스텝마다 PASSED/FAILED를 판정하고, 그 과정이 trace로 녹화된다. 녹화된 trace는 엔드투엔드로
돌려 봐야 할 때 모델 없이 재생된다. 시나리오가 기준이다. 앱이 스텝과 다르게 움직이면 앱이 틀린 것이고, 모델은 길을 찾아 고쳐 가지
않고 그 스텝을 FAILED로 보고한다. 한 스텝이 FAILED면 뒤는 전부 SKIPPED다.

## 자연어로 할 수 있는 것

동작 (스텝 하나 = 동작 하나):

- 탭 — `"보관함" 탭을 누른다`
- 입력 — `"검색" 필드에 "타짜"를 입력한다`. 값은 통째로 들어간다(접근성 set-text, 키보드를 거치지 않는다).
- 스크롤 — `아래로 스크롤해 "설정"을 찾는다`. 이미 보이면 스크롤 없이 넘어간다.
- 뒤로 가기 — `뒤로 간다`

확인 (현재 화면만 본다, 조작하지 않는다):

- 라벨·상태 — `"보관함" 탭이 selected 상태인지 확인한다`, `"등록된 쿠폰" 목록이 보이는지 확인한다`
- 한 문장에 기대 여럿을 묶을 수 있다. 하나라도 거짓이면 그 스텝은 FAILED.

못 하는 것 (스텝으로 쓰지 않는다):

- 롱프레스, 더블탭, 두 손가락 제스처, 드래그, 화면 회전.
- 콘텐츠 정합성("영화만 나오는가", 특정 작품 제목, 가격). 매번 바뀌어 재생이 판정하지 못한다. 사람이 봐야 하면
  설명문에 "영상에서 볼 것"으로 적고 스텝은 거기까지 가는 조작만.
- 개수 세기, 조건 분기("…이면 …한다"), 앞 스텝의 값을 기억해 비교하기.
- 없음 확인("…이 없는지"). 재생이 가리지 못한다. 대신 나타나는 것을 쓴다.
- 기다리기, 앱 켜기. 러너가 앱을 띄우고 화면이 그려질 때까지 기다린 뒤 첫 스텝을 시작한다.

## 파일 형식

`.simul/scenarios/<그룹>/<이름>.md`. 파일 하나 = 상태 하나 + 흐름 하나.

```markdown
---
name: search-query
tags: [search]
setup:
  appState: member-basic
  deeplink: example://search
---

검색 화면에서 검색어를 입력하고 "작품" 탭으로 좁히면 그 탭이 선택된다.

1. "검색" 필드에 "타짜"를 입력한다
2. "작품" 탭을 누른다 :: "작품" 탭이 selected 상태다
3. "작품" 탭이 selected 상태인지 확인한다
```

- `name`, `tags`가 리포트와 `simul list`에 쓰인다. `title`, `owner`는 선택.
- `setup`이 진입이다. `appState`(또는 `clearData: true`)로 전제 상태를, `deeplink` 또는 `launch: true`로 시작
  화면을 정한다. 모든 시나리오가 전제 상태를 선언한다. 스냅샷 만들기, 딥링크·런치 선택, 기기 설정·앱 언어는
  [setup.md](references/setup.md).
- **번호 리스트만 실행된다.** 설명문은 사람용이고 리포트의 시나리오 페이지에 영상 옆에 그대로 보인다. 그 화면을
  모르는 사람이 읽어도 무엇을 확인하는지 알게 한두 문장.

## 스텝 문장

스텝은 한국어나 영어 문장 하나. 라벨은 **화면에 보이는 그대로** 따옴표에 넣는다. 따옴표는 요소의 `text`,
`contentDesc`, `resourceId`에 동등하게 매칭되고, 재생은 그 따옴표를 증거로 쓴다.

1. **한 스텝 = 한 동작.** "검색하고 첫 결과를 누른다"는 두 스텝. 문장은 앞뒤 스텝 없이도 읽히게 자기완결적으로.
2. **애매하지 않게.** "닫기 버튼 쪽을 선택한다"가 아니라 `"닫기"를 누른다`. "입력한다"가 아니라
   `"검색" 필드에 "타짜"를 입력한다`. 모델은 쓴 대로만 하고 비슷한 요소로 바꿔 누르지 않는다.
3. **라벨은 추측하지 않는다.** 코드의 문구가 화면에 그대로 나오는지는 확인 전까지 모른다. 모르면 그 화면에서
   `android layout`을 떠서 `text`/`contentDesc`/`resourceId`를 본다. 세 속성이 모두 없는 요소는 지목할 수
   없다. 이웃이나 위치로 우회하지 말고 앱에 노출(testTag·contentDescription)이 필요하다고 보고한다.
4. **앵커는 고정된 것만.** resourceId/testTag → 그 화면에 유일한 고정 문구 순. 콘텐츠 제목, 배너 문구, 개수 배지는
   타겟으로도 확인으로도 쓰지 않는다. 라벨 일부만 고정이면 그 부분만 따옴표에(부분 일치):
   `"Change payment method" 행을 누른다`.
5. **같은 라벨이 여러 개면 AMBIGUOUS로 멈춘다.** 더 구체적인 라벨이나 resourceId로.
6. **스크롤은 써 준다.** 안 보이는 타겟을 모델이 스크롤해 찾긴 하지만, 방향을 적어 주면 헤매지 않는다:
   `아래로 스크롤해 "설정"을 찾는다`. 이미 보이면 스크롤 없이 넘어간다.

## 기대 결과: `::`

액션 스텝은 화면이 바뀌면 통과다. 액션의 결과가 그것만으로 안 보이면 **그 스텝에 `::`로** 기대를 붙인다.
같은 줄에 ` :: `로 잇거나, 바로 아랫줄에 `:: `로 시작하는 줄을 둔다.

```markdown
2. "등록" 버튼을 누른다 :: "등록된 쿠폰" 목록이 보인다
3. 뒤로 간다
   :: "쿠폰" 화면이 다시 보이고 "등록된 쿠폰" 목록이 남아 있다
```

- 기대는 모델이 액션을 끝낸 **뒤에** 전달된다. 모델은 목표를 보고 길을 찾는 게 아니라, 이미 받은 화면 변화로
  기대가 맞는지만 판정한다. 안 맞으면 FAILED.
- 뻔한 전환에는 붙이지 않는다. 탭을 눌러 화면이 바뀌는 건 액션 자체가 증명한다. 복원, 불변, 다른 화면에
  반영된 결과처럼 액션만으로는 알 수 없는 것에만.
- 기대에도 따옴표 앵커를 넣는다. 그 따옴표가 재생의 증거다.

## 확인 스텝

`… 확인한다` / `Verify …`로 시작하는 스텝은 현재 화면에 대한 assert다. 모델은 탭도 스크롤도 하지 않고
지금 레이아웃만 보고 판정한다. 지금 화면에 없으면 없는 것이다.

- 붙일 액션이 없을 때 쓴다. 흐름의 끝을 닫을 때, 흐름 중간에 상태를 꼭 짚어야 할 때.
- 매 액션 뒤에 확인을 붙이지 않는다. 액션은 화면이 안 바뀌면 그 자체로 FAILED다.
- 반드시 따옴표 앵커를 넣는다. `"보관함" 탭이 selected 상태인지 확인한다`. 앵커 없는 확인은 재생이 가릴 수 없다.

## 쓴 뒤 체크

- 스텝마다: **이 액션이 안 먹혔다면 이 스텝은 FAILED가 됐을까?** 가장 위험한 건 실패가 아니라 통과하는 오탐이다.
- 마지막 스텝은 고정 앵커로 결과를 확인하며 닫는다.
- 이전 화면에도 있던 라벨은 도착의 증거가 못 된다. resourceId로.
- 기존 시나리오와 화면·동작·상태가 겹치지 않는다.

## 돌려 보기

```bash
simul run search/search-query.md --mode llm   # 모델이 녹화하며 수행. 경로는 .simul/scenarios/ 기준
```

HTML은 만들지 않는다. stdout에 스텝별 모델의 턴 로그(툴 호출과 report 이유)가 흐르고, 마지막 줄이
`PASSED|FAILED: <name> (…ms, report: <dir>)`다. `--mode llm`을 빼면 trace가 있을 때 그 trace를 재생하고
없으면 SKIP하므로, 쓰거나 고치는 중에는 항상 붙인다.

실패하면 `<dir>`(`.simul/reports/<stamp>/`)에서 본다:

- `result.json` — `steps[]`의 `status`, `reason`(모델이 15단어로 적은 이유), `evidence_expected`/`evidence_found`.
  멈춘 스텝이 어디고 모델이 뭘 봤는지는 여기서 끝난다.
- `layout/NN.json` — 그 스텝이 끝난 시점의 레이아웃. 라벨을 틀리게 썼으면 여기 실제 `text`/`contentDesc`/`resourceId`가 있다.
- `steps/NN.png`, `screenshots/` — 스텝 끝 화면과 액션마다의 화면. 모델이 어디서 헤맸는지.
- `logcat.txt` — 크래시, 딥링크 수신, `Fully drawn`.

고칠 곳은 셋 중 하나다. 라벨·앵커가 틀렸으면 시나리오. 스텝 하나에 동작이 여럿이라 모델이 헤맸으면 스텝을
쪼갠다. 시나리오대로 썼는데 앱이 다르게 움직였으면 앱이고, 시나리오는 그대로 둔다.

통과하면 md 옆에 `<이름>.trace.json`이 생긴다. md와 함께 커밋한다. 사람에게 보여줄 HTML 리포트는
`simul report <파일>`, 수동으로 돌리거나 상태 스냅샷을 만들 때는 `simul`(TUI).
